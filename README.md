# PIC Data Manager

A data infrastructure and analysis platform for photonic integrated circuit (PIC) design, fabrication, and testing workflows. Built to demonstrate end-to-end handling of PIC data through unified pipeline that ingests data from all three sources, flags anomalous devices automatically, and makes the process-performance relationships easy to explore without writing SQL by hand.

---

## What's in here

```
pic-data-manager/
├── data/                       # Raw JSON records (designs, fabrication, tests)
├── models/                     # Trained neural network weights + normalization params
├── scripts/
│   ├── seed_data.py            # Generates synthetic but realistic PIC datasets
│   ├── ingest_jsons.py         # Loads JSON files into SQLite
│   ├── run_ai.py               # Anomaly detection via IsolationForest
│   ├── analyze_performance.py  # Foundry comparisons + correlation analysis
│   └── train_model.py          # Neural network to predict insertion loss from fab params
├── app.py                      # Streamlit dashboard (6 tabs + NL query interface)
├── pic_data.db                 # SQLite database (generated by the pipeline)
└── requirements.txt
```

## Setup

```bash
pip install -r requirements.txt
```

Then run the pipeline in order:

```bash
python3 scripts/seed_data.py
python3 scripts/ingest_jsons.py
python3 scripts/run_ai.py
python3 scripts/analyze_performance.py
python3 scripts/train_model.py
```

Launch the dashboard:

```bash
python3 -m streamlit run app.py
```

Opens at `http://localhost:8501`. The pipeline only needs to re-run when the underlying data changes.

## The pipeline in more detail

**Data generation (`seed_data.py`)**

Produces 30 device designs, 90 fabricated wafers (3 per design across 3 foundries), and 2,700 test records. Each foundry has distinct process characteristics which creates realistic variation in device yield and optical performance. Useful as a stand-in until real fab data is available.

**Ingestion (`ingest_jsons.py`)**

Validates required columns and loads the three source files into a SQLite database. The schema keeps designs, fabrication metrology, and test results in separate tables linked by `design_id` and `wafer_id`. Running this again replaces existing tables, so it's safe to re-ingest after data updates.

**Anomaly detection (`run_ai.py`)**

Joins all three tables and runs scikit-learn's IsolationForest across 13 numeric features covering both process conditions and optical performance. Flags roughly the top 5% of devices as anomalous. The joined result (including the `ai_flagged_anomaly` column) is saved as its own table so the dashboard can query it directly.

IsolationForest was used as it doesn't require labeled failure data.

**Performance analysis (`analyze_performance.py`)**

Two things: a per-foundry summary (yield rate, average insertion loss, bandwidth, defect count, etc.) and a full Pearson correlation matrix between fabrication process parameters and device performance metrics. The strongest signal in the synthetic data is defect count correlating with insertion loss, which tracks with physical intuition.

**Neural network prediction (`train_model.py`)**

Trains a small feedforward neural network (PyTorch) that learns to predict insertion loss from six fabrication parameters: defect count, sidewall roughness, width error, film thickness, etch depth, and measured width. The network has two hidden layers (16 → 8 neurons) and trains for 500 epochs using the Adam optimizer and mean squared error loss.

Before training, all input features are normalized to zero mean and unit variance so that parameters with very different scales (e.g. defect count vs. film thickness in nm) don't distort the learning. The normalization parameters are saved alongside the model weights so the same transformation can be applied to new data at inference time.

After training, predictions are saved to the `model_predictions` table with the actual insertion loss, the predicted value, and the residual. Model performance is reported as MAE and RMSE in dB.

Trained weights are saved to `models/insertion_loss_net.pt` and normalization parameters to `models/norm_params.npz`.

## Dashboard

Six tabs covering the full data lifecycle, plus a natural language query interface:

- **Overview** — yield by foundry, defect distributions, film thickness vs bandwidth
- **Designs** — full design table with simulated performance specs
- **Fabrication** — metrology data, roughness distributions, process recipe breakdown
- **Test Data** — raw test results with pass/fail filtering
- **AI Insights** — anomaly scatter plots, flagged device breakdown by foundry
- **Process Analysis** — correlation heatmap, process vs performance scatter plots
- **Ask** — type a question in plain English, get the generated SQL and a Claude interpretation side by side

---

## Database schema

| Table | Description |
|---|---|
| `designs` | Device geometry and simulation specs |
| `fabrication` | Wafer-level metrology from each foundry |
| `tests` | Optical test results per device |
| `joined_ai_results` | Full join of the above + anomaly flags |
| `foundry_performance_summary` | Aggregated yield and performance per foundry |
| `process_performance_correlations` | Pearson r between process params and metrics |
| `model_predictions` | Actual vs. predicted insertion loss + residuals per device |
